# 播放页评论侧栏

分支：`feature/player-comments`。本功能为独立测试版，尚未合入 main，
不包含在已发布的 v0.2.0 中。

## 布局和操作

- 播放时按「上」，在播放设置里选择「评论」。
- 评论复用右侧播放设置区域（1920 × 1080 设计坐标中的右侧 560 像素）。
  同一个 Video 节点缩至左侧 1360 × 765，保持 16:9 并垂直居中。
  打开／关闭评论不替换播放地址，不改变播放进度或暂停状态。
- 看评论时临时关闭弹幕，清除正在显示的弹幕。关闭评论后恢复保存的开关，
  按当前视频进度重新同步。临时关闭不会写入 `dm_on` 偏好；
  阅读期间若手机主动修改弹幕开关，退出时使用最新选择。
- 上下选择评论；OK 阅读全文；全文页上下滚动；右键查看该评论的回复。
  根评论全文页也可用 OK 查看回复。
- 返回键／左键逐级返回（全文 → 列表、楼中楼 → 原评论、主列表 → 全屏播放）。
  专用播放／暂停键控制视频，评论中的 OK 不切换播放状态。

## 首版范围

- 热门评论、置顶标记、UP 主标记、赞数、回复数及发布时间。
- 评论全文和楼中楼分页；评论图片暂显示文字占位，表情依照现有字体覆盖处理。
- 每页 20 条，在接近页尾时预取下一页；每个层级最多缓存 3 页。
  屏幕仅复用两个评论卡片，避免为整页评论创建大量文字节点。
- 请求使用现有 BiliTask 和登录信息，只读评论，不点赞、不发评论、不消耗硬币。
  尚未登录也会尝试请求；接口限制或网络失败时显示原因并提供重试。
- 换视频时取消旧请求并清空评论。关闭侧栏取消未完成请求，同一视频重开可复用已读页；
  分 P 共享同一个视频评论区。
- 暂不提供最新评论排序、评论图片展示、时间戳跳转、评论点赞或发表回复。

## 验证

自动检查直接执行生产 BrightScript 函数，网络、SceneGraph 节点和解码器使用测试替身。
数据为合成内容，不读写电视，也不使用账号：

```sh
npm install --prefix build/comments-test-runtime --ignore-scripts brs@0.45.0
python tests/ui/run_comments.py
```

覆盖：长 ID、置顶去重、缺字段、空列表、图片占位、请求参数、接口失败、
预取不跳焦点、前后翻页、楼中楼返回位置、换视频／关闭后的过期响应、
翻页失败保留列表、弹幕偏好恢复，以及打开／关闭不重载或暂停视频。

另需通过 BrighterScript 编译和频道包引用检查。
上述检查不能证明 Roku 真机的文字排版和视频缩放观感。

### 本次实机记录

在当前 Roku TV 上安装测试包，并使用现有登录状态验证：

- 热门评论与楼中楼均可翻到第 2 页，再返回上一页／原评论。
- 全文获得焦点，返回列表后释放焦点。实测发现「只给父节点焦点」不足以让
  隐藏的 ScrollableText 退出焦点链，已改为显式释放。
- 暂停状态下完成全文、楼中楼、翻页和收起，播放器位置一直为 1.273 秒；
  界面树的视频区域由 `{0,158,1360,765}` 恢复为 `{0,0,1920,1080}`。
- 原先开弹幕：阅读时节点隐藏，关闭恢复；原先关弹幕：退出后仍关闭。
  本轮测试结束恢复原先关闭的偏好。
- 阅读时视频位置继续增长；专用播放键和同一手机投屏协议的暂停／继续可用。
- 通过手机投屏协议切换另一条视频后，旧侧栏关闭，新视频可重新读取自己的评论。
  协议命令由本机测试客户端直接发到电视，没有增加常驻桥接或手机软件。
- 匿名直接请求本次样本只返回 3 条热门评论，第二页为空；电视登录状态下可正常翻页。
  匿名／受限账号的完整评论数量由服务端决定。

60 项本地断言通过；BrighterScript 与电视端编译通过。测试包未修改版本号，
尚未合入 main 或发布。

仍有明确边界：

- 开发者截图与此前一样出现花屏，不能据此判断电视实际画面；排版观感、
  长全文的连续滚动，以及缩放瞬间的视觉效果仍需实际观看确认。
- 手机协议在暂停时跳转会恢复播放，并可能落在目标前的关键帧：
  请求 60 秒时观测到约 55.77 秒。关闭评论后的基线也有相同行为，
  本分支没有修改既有跳转逻辑；该问题另行处理。
- 接口故障和过期请求由合成响应验证，没有通过断开用户网络或注销账号测试。
