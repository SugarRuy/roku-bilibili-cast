# 视频列表首次滚动卡顿

## 状态

2026-11-14。工作分支 `fix/grid-scroll-stutter`，基于 main 的 `969b776`。
视频网格修复已完成本机实测，按用户确认以 `--no-ff` 合入 main 并推送。
本次合并不发布新版本；弹幕、品牌和播放功能不在本次改动范围内。

## 实机定位

仅测 API 和追加节点耗时不足以证明滚动流畅。第一轮虽然把单批接入降到约
8–12 ms，用户仍能看到首次下滑停顿。随后用 Roku Perfetto 的 render /
swapBuffers 记录了相同的“下 10 次、上 10 次、再下 10 次”。

- 原测试版首次下滑出现约 150–307 ms 的帧间隔；第二次下滑约 11–12 ms。
- 保留图片、播放量、时长，只隐藏标题和 UP 主文字：三个方向均显著平稳。
- 去掉封面仍会卡顿，说明主要问题不是封面下载。
- SimpleLabel、提前 boundingRect、把字体复制到 tmp、滚动结束后再显示文字等
  方案没有通过完整验收，未保留。中间有缺字版本，其低帧间隔不计为成功。

## 当前实现

1. 保留第一轮的 Task 构建 ContentNode、提前分页、40 ms 分批接入、刷新和请求身份保护。
2. BiliTask 使用随包字体，把标题两行和 UP 主／日期文字预先绘制成一张透明 PNG。
   VideoCard 显示准备完成的图片；封面、播放量、时长、进度和焦点仍用原有组件。
   适配普通网格 414 px 和搜索网格 350 px，保留两行标题及省略号。
3. 字体、宽度和完整文字参与缓存键。文件先写入临时文件，再重命名并发布 URI。
   缓存仅在电视 App 的 tmp 目录，约两千份上限；已有缓存可复用。准备或加载失败
   会回退原生文字，不用空白标题代替失败结果。
4. 滚动期间让文字准备任务等待，在图形操作之间让出执行时间。增加分页提前量，
   退出标签页时取消其未完成请求，避免为离开的页面继续准备文字。
5. 放宽时长角标的数字宽度，避免部分时间被显示成 `3:…`。

没有电脑桥接、后台电脑服务或手机安装包。所有图片准备均在 Roku 上执行。

## 验证结果与限制

设备：Roku TV M302X / Roku OS 16.0.4.853。

| 验证 | 结果 |
| --- | --- |
| 正常间隔，首次下滑 10 次 | 最长渲染帧间隔约 26 ms |
| 快速连按，首次下滑 10 次 | 最长约 27 ms；未丢失焦点移动 |
| 快速连按，回滑 10 次 | 最长约 47 ms，仍有个别短波动 |
| 快速连按，第二次下滑 10 次 | 最长约 13 ms |
| 三阶段文字核对 | 每阶段检查当前两排 8 张卡片；标题图片已加载，时长等文字完整 |
| 视觉核对 | 414 px 网格截图确认中文、两行标题、省略号、作者、日期与时长可读 |
| 分页 | 快速三阶段从 40 项增至 80 项，焦点 0 → 40 → 0 → 40 |
| 搜索 | 返回 30 项，350 px 文字图片加载成功；搜索布局未做独立帧统计 |
| UP 主列表 | 20 次上下移动，60 → 90 项，焦点 0 → 48，焦点与分页检查通过 |
| 图片失败回退 | 注入不存在的 PNG URI，确认恢复原生标题和作者文字；测试后已恢复正式测试包 |

这些是原生渲染事件间隔，不是摄像机测得的面板刷新率。主要的 0.2–0.3 秒停顿
已明显降低，但不能声称完全没有掉帧。首次准备 20 条文字仍需要约 1.7–2.4 秒（30 条样本约 3.3 秒）；
连续快速滚动时任务主动等待，日志的总准备时间可更长。提前请求页面和文字缓存
用于覆盖这段时间；较慢的网络仍可能使用户等到页尾。

收藏夹、UP 主网格沿用同一 414 px 路径。搜索及 UP 主的后续开发者截图返回黑帧，
因此只将节点、图片加载状态、焦点与分页检查记为通过，不宣称后续截图视觉通过。本轮不声称覆盖所有字体、所有低端 Roku
设备或极长列表；其它设备如果不支持此图形路径会保留原生文字回退。

## 复现

`tests/ui/grid_scroll_probe.py` 核对焦点和分页；ECP 响应耗时不能当成帧时间。
`tests/ui/analyze_grid_trace.py` 离线分析已记录的 Perfetto trace，检查最后三组方向键，
输出每次滚动的帧数、最长 render 耗时和帧间隔。需要 Python 的 `perfetto` 包。

使用 Roku 官方 ECP `/perfetto/enable/dev` 和 `/perfetto-session` WebSocket 录制时，
必须在新 SDK 进程真正启动后再连接，避免误录旧进程。录制后关闭连接；系统的
启用标记要在电视重启后才清除。不要把诊断包当成发布包。
本轮采集连接已关闭；远程快捷键未能确认系统重启，启用标记待下次正常电视重启清除。

原始 trace、XML、截图和失败实验保存在忽略目录 `build/stutter-investigation/`，
不提交到仓库。有效记录为 `render-cached-text` 和 `render-cached-text-fast`。
