# 播放页与弹幕改进计划

本计划依据当前 Roku 客户端代码和 2026-11-13 在一台 Roku TV（M302X）上的诊断结果。云视听小电视的实际播放设置页尚未核实，因此下文的新增选项是待实现的产品方案，不代表该客户端已经具备完全相同的功能。

## 当前状态

| 功能 | 当前实现 | 问题 |
| --- | --- | --- |
| 弹幕开关 | 播放时按“上”，在侧栏第二项切换；首页设置还有默认开关 | 入口不明显，用户很容易以为没有开关 |
| 不透明度、显示区域 | 侧栏和首页设置均可调整 | 只有这两种细化设置 |
| 弹幕样式 | 42 像素文字、滚动／顶部／底部三种模式 | 字号、速度、密度和模式均不可单独调整 |
| 播放列表 | 按“下”打开分 P 和相关推荐，控制栏有文字提示 | 没有醒目的可操作入口 |
| 画质 | 播放页只显示当前画质；播放 API 自动选择 | 无法手动切换清晰度 |
| 播放速度 | 使用 Roku `Video` 节点的默认速度 | 无速度菜单，平台能力待验证 |

对应代码：`channel/components/widgets/PlayerPanel.brs`、`channel/components/widgets/DanmakuLayer.brs`、`channel/components/screens/PlayerScreen.brs`、`channel/components/bili/ops.brs`。

## 卡顿诊断

同一公开视频的弹幕 XML 含 3,598 条可解析记录；现有加载逻辑按每秒最多 12 条筛到 990 条。连续播放时约每 5 秒出现 16–37 条弹幕。电视报告视频在播放、缓冲满，播放进度连续增长。

诊断包记录到弹幕计时器通常每约 200 毫秒触发一次；进入稳定播放后最长间隔约 276 毫秒，单次处理最长约 7 毫秒，文字宽度测量最长约 3 毫秒。最初进入播放时有一次约 1.8 秒的间隔，属于启动阶段。现有日志无法直接测量电视每帧绘制弹幕的时间，因此用户观察到的半秒至一秒暂停尚不能归因于网络、计时器或文字测量；大量同时运动的文字节点是下一步要验证的方向。原版每集预建 64 组动画、128 个文字节点，即使弹幕关闭也会创建。

## 实施顺序

### 1. 先解决弹幕停顿

- 给诊断版补充同时显示的弹幕数和动画更新间隔；固定同一视频片段、画质与显示区域进行对比。
- 分别试运行较低并发数、简化阴影、减少场外动画节点，观察电视端弹幕是否仍有可见停顿。以实际效果选实现，不仅凭 BrightScript 耗时作结论。
- 增加“流畅／标准／丰富”密度预设；标准档应适合当前电视，丰富档允许用户主动选择更多弹幕。加载时保留足够的数据，密度过滤放在显示阶段，切换预设无需重新下载整集弹幕。
- 验收：同一密集弹幕片段持续播放 2 分钟，弹幕不再出现可见的半秒级定格；视频播放和投屏控制正常；开关弹幕即时生效。

### 2. 让基础操作容易找到

- 将现有的小字按键提示改成醒目的弹幕状态和设置入口；打开侧栏时优先选中弹幕开关。
- 侧栏分为“弹幕”和“播放”两组，保留 Roku 遥控器上下选择、左右调整的方式。控制栏隐藏后不遮住视频。
- 验收：首次使用者从播放页至多两次按键就能关掉弹幕，再次打开能恢复原设置；遥控器“下”仍可打开选集和相关推荐。

### 3. 补齐常用弹幕选项

- 在现有开关、不透明度、显示区域之外，加入字号、滚动速度、密度，以及滚动／顶部／底部的独立显示开关。
- 这些选项先保存在电视本地，对当前视频即时生效，并用于后续视频。字号或速度改变时重算占用车道和动画时长，避免重叠或突然跳动。
- 关键词和用户屏蔽放在后续阶段：需要先决定遥控器输入方式、规则存储，以及是否接入 B 站账号的屏蔽规则。当前解析后的弹幕数据没有保留用户标识。

### 4. 扩展其他播放控制

- 加入手动画质选择。播放 API 当前固定请求最高可用画质；需返回实际可用档位，切换时保留进度，并在不可播放时回退。
- 倍速播放先做 Roku `Video` 节点能力验证；确认普通点播和投屏都支持目标倍速后再设计菜单和控制协议。
- 字幕／音轨选择需要单独核实内容 API 和 Roku 播放器支持情况，之后再排期。

## 提交组织

按功能分支和提交推进：`fix/danmaku-rendering`、`feature/danmaku-controls`、`feature/player-quality`；倍速验证结果单独记录。每个功能先在开发者安装版上测试，再合并发布。项目名称暂不更改。
